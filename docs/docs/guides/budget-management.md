# Budget Management

Hekate tracks every LLM call and enforces spending limits at daily, monthly, and per-project levels. The budget system uses in-memory reservations to prevent concurrent tasks from exceeding limits.

---

## How Cost Tracking Works

Every LLM API call records:

| Field | Description |
|-------|-------------|
| `prompt_tokens` | Input tokens sent to the model |
| `completion_tokens` | Output tokens generated by the model |
| `cost_usd` | Computed cost based on model pricing |
| `provider` | Which provider was used (claude_code, ollama, etc.) |
| `model` | Specific model name |
| `project_id` | Associated project |
| `task_id` | Associated task |
| `purpose` | What the call was for (execution, verification, planning) |
| `timestamp` | Unix timestamp |

These records are stored in the `usage_log` table and form the basis for all analytics.

### Pipeline cost tracking (Tyche)

In the gods pipeline, Tyche records spend after each `worker_event:completed`:

```python
# Tyche emits a budget_spent event with cost details
Emit("budget_spent", {
    "task_id": task_id,
    "project_id": project_id,
    "cost_usd": cost_usd,
    "model_used": "claude-sonnet-4-20250514",
})
```

## Budget Configuration

Budget limits are set in `orchestration/config.json`:

```json
{
  "budget": {
    "daily_limit_usd": 5.0,
    "monthly_limit_usd": 50.0,
    "per_project_limit_usd": 10.0,
    "warn_at_pct": 80
  }
}
```

| Setting | Default | Description |
|---------|---------|-------------|
| `daily_limit_usd` | 5.0 | Maximum spend per calendar day (UTC) |
| `monthly_limit_usd` | 50.0 | Maximum spend per calendar month (UTC) |
| `per_project_limit_usd` | 10.0 | Maximum spend per individual project |
| `warn_at_pct` | 80 | Warning threshold as percentage of limit |

When a limit is reached, the `BudgetManager` raises `BudgetExhaustedError` and new dispatches are blocked until the next period rolls over (or the project limit is increased).

!!! warning "Reservation tracking"
    The budget manager uses in-memory reservations to prevent TOCTOU races. When two tasks try to dispatch concurrently, an `asyncio.Lock` ensures only one can check-and-reserve at a time. Reservations are approximate -- a task reserved before midnight but completing after creates a brief stale reservation that self-corrects on period rollover.

## Model Pricing

### API-billed models

These models incur per-token costs when called through the Anthropic API:

| Model | Input (per 1M tokens) | Output (per 1M tokens) | Notes |
|-------|----------------------|------------------------|-------|
| Claude Haiku | $1.00 | $5.00 | Fast, cheap -- used for verification, extraction |
| Claude Sonnet | $3.00 | $15.00 | Balanced -- default for most tasks |
| Claude Opus | $15.00 | $75.00 | Most capable -- complex reasoning |
| Gemini Pro | $1.25 | $10.00 | Currently disabled (auth broken) |
| Gemini Flash | $0.15 | $0.60 | Currently disabled (auth broken) |

### CLI-billed providers

These providers use subscription billing -- the per-call API cost is effectively $0:

| Provider | Billing | Notes |
|----------|---------|-------|
| `claude_code` | Claude Code subscription | Primary executor. $0 per API call. |
| `gemini_cli` | Google AI Studio | Disabled (exit code 1, auth broken) |
| `codex_cli` | ChatGPT Plus subscription | Disabled (subscription broken) |
| `ollama` | Local hardware | Free. Runs on local GPU. |

!!! tip "CLI-first cost model"
    Because CLI providers are subscription-billed, most task execution costs $0 per call. The budget system still tracks these calls (with `cost_usd = 0.0`) for analytics and throughput monitoring. API-billed models are used primarily for planning (Athena) and verification (Mimir) through the LLM Gateway.

## Provider Quotas

Provider quotas enforce rate limits with configurable time windows:

| Setting | Description |
|---------|-------------|
| `rate_limit_per_frequency` | Max calls within the window |
| `rate_limit_frequency_seconds` | Window duration in seconds |

These are set per task type in the `TaskDefinition`:

```python
TaskDefinition(
    rate_limit_per_frequency=10,
    rate_limit_frequency_seconds=60,  # 10 calls per minute
)
```

When a quota is hit, the task is deferred (not failed) until the window resets.

## Budget Gate in the Pipeline

Before Odin dispatches a task, Tyche runs a budget check:

```python
result = await tyche_check_budget(event, db, budget_remaining=4.50)
# result: {"allowed": True, "reason": "Budget OK: $4.50 remaining"}
# or:     {"allowed": False, "reason": "Budget exhausted (remaining: $0.00)"}
```

If the budget check fails:

1. The task stays in `pending` state
2. No retry is consumed
3. The next pipeline tick re-evaluates the budget
4. If budget is permanently exhausted, the project stalls

## Analytics Endpoints

The orchestration API provides three analytics endpoints (admin-only):

### Cost Breakdown

```
GET /api/admin/analytics/cost-breakdown?days=30
```

Returns:

- **By project**: Total cost and task count per project
- **By model tier**: Aggregate cost per model
- **Daily trend**: Day-by-day cost over the time window

```json
{
  "by_project": [
    {"project_id": "abc123", "project_name": "Auth System", "cost": 2.45, "task_count": 12}
  ],
  "by_model_tier": [
    {"model_tier": "claude_code", "cost": 0.0, "call_count": 45},
    {"model_tier": "haiku", "cost": 0.32, "call_count": 30}
  ],
  "daily_trend": [
    {"date": "2026-03-30", "cost": 0.45},
    {"date": "2026-03-31", "cost": 0.12}
  ]
}
```

### Task Outcomes

```
GET /api/admin/analytics/task-outcomes?days=30
```

Returns:

- **By tier**: Success/failure/cancel counts per provider
- **Verification results**: Pass/gaps/human-needed per tier
- **Retry rates**: Average retries per provider

### Efficiency Metrics

```
GET /api/admin/analytics/efficiency?days=30
```

Returns:

- **Cost per completed task**: By provider
- **Wave throughput**: Tasks completed per wave across projects
- **Time-to-completion**: Average execution duration by complexity

## Monitoring Budget Usage

### Check current status

```bash
curl http://localhost:5200/api/usage/budget \
  -H "Authorization: Bearer $TOKEN"
```

### Watch for warnings

The budget manager logs warnings at the `warn_at_pct` threshold:

```
WARNING: Daily budget at 82% ($4.10 / $5.00)
WARNING: Project "Auth System" budget at 91% ($9.10 / $10.00)
```

### Pipeline-level monitoring

Tyche emits `budget_spent` events that can be observed in the event stream:

```bash
curl http://localhost:5200/api/events/PROJECT_ID?token=SSE_TOKEN
```

Budget events appear alongside task lifecycle events in the SSE stream.

!!! note "Budget resets"
    Daily budgets reset at midnight UTC. Monthly budgets reset on the first of each month. Per-project budgets persist for the lifetime of the project and do not reset.
